# Бот-аналітик інвестиційних пропозицій

Окремий Telegram-бот (не плутати з `../bot.py` і `../crm/telegram_bot.py`):
ви скидаєте йому сайт забудовника, все, що надіслав менеджер проекту
(файли, фото, посилання, текстові нотатки), а він:

1. Одразу дає коротку реакцію на кожен новий матеріал (що це, які ключові
   цифри, чи є щось підозріле).
2. Складає копію кожного матеріалу в Google Диск, у папку «Ринок» →
   підпапка з назвою проекту.
3. За командою `/analyze` — зведений інвестиційний аналіз по всіх
   матеріалах проекту (сильні сторони, ризики, чого бракує).
4. Відповідає на довільні питання по проекту («яка орендна ставка в
   фінмоделі для готелю?») і вказує, з якого саме документа взяв
   відповідь.
5. Все зберігається назавжди в базі бота — через місяць/рік можна питати
   `/compare` одразу по ВСІХ збережених проектах («який з проектів
   дохідніший», «де зараз безпечніше вкладати»): бот зіставляє факти з
   різних проектів і окремо позначає, де це цифра з ваших документів, а
   де — загальні міркування, яких у документах немає.

## Як це працює

- `db.py` — SQLite (`investor.db`): проекти, матеріали, текстові
  фрагменти (`chunks`) з прив'язкою до місця (сторінка/аркуш/абзац) —
  саме вони йдуть у відповідь як «Джерело: ...».
- `extract.py` — дістає текст із PDF (`pypdf`), DOCX (`python-docx`),
  XLSX (`openpyxl`, по аркушах і клітинках), текстових файлів, сайтів
  (`requests` + `beautifulsoup4`) і зображень (опис через Claude vision).
- `drive.py` — Google Drive API: створює/знаходить папку «Ринок» і
  підпапку проекту, вантажить туди кожен файл/нотатку.
- `retrieval.py` — простий пошук релевантних фрагментів під питання (за
  перетином слів, без embeddings) — достатньо для десятків документів на
  проект.
- `analysis.py` — промпти до Claude: швидка реакція на матеріал, зведений
  звіт, відповідь на питання з цитуванням джерела.
- `bot.py` — Telegram-хендлери (`pyTelegramBotAPI`, polling).

## Локальний запуск

```bash
cd investor_bot
cp .env.example .env      # заповніть токени, див. нижче
pip install -r ../requirements.txt
export $(cat .env | xargs)
python bot.py
```

## Що потрібно від вас

1. **Telegram-бот**: [@BotFather](https://t.me/BotFather) → `/newbot` →
   токен → `TELEGRAM_INVESTOR_BOT_TOKEN`.
2. **Anthropic API-ключ** → `CLAUDE_API_KEY` (можна той самий, що вже
   використовується в `bot.py`).
3. **Google Диск** (якщо хочете, щоб бот справді копіював файли в папку
   «Ринок» — без цього кроку бот працюватиме, просто без копій на Диску):
   1. [console.cloud.google.com](https://console.cloud.google.com) →
      створіть проект → увімкніть **Google Drive API**.
   2. IAM & Admin → Service Accounts → **Create Service Account** →
      Keys → **Add Key → JSON** — завантажиться файл ключа.
   3. Вміст цього JSON-файлу (весь, одним рядком) → `GOOGLE_SERVICE_ACCOUNT_JSON`.
   4. На вашому Google Диску створіть (або оберіть) папку, у якій має
      з'явитись «Ринок», і розшаріть її на email сервісного акаунта
      (виглядає як `...@...iam.gserviceaccount.com`, є в JSON-ключі та
      в консолі) з правами **Редактор**.
   5. ID цієї папки (з посилання `drive.google.com/drive/folders/<ID>`)
      → `GOOGLE_DRIVE_PARENT_FOLDER_ID`.
   6. Сервісний акаунт не має власного «Мого диска» — без спільної папки
      на кроці 4 завантаження файлів впаде з помилкою квоти, тому цей
      крок обов'язковий.
4. **Хостинг 24/7**: у корені репозиторію `Procfile` вже містить рядок
   `investor-bot: python investor_bot/bot.py` — на Railway/Render можна
   запустити як окремий сервіс із того самого репозиторію, вказавши
   змінні середовища з `.env.example`.

## Як користуватись

```
/project Готель "Панорама"     — створити/перемкнути активний проект
(надсилаєте сайт, PDF, Excel-фінмодель, фото, текстові нотатки)
яка орендна ставка в фінмоделі?  — питання по активному проекту
/analyze                        — зведений аналіз усіх матеріалів проекту
який проект дохідніший?         — питання одразу по ВСІХ проектах (або /compare ...)
/status                         — активний проект, кількість матеріалів, посилання на Диск
/projects, /use Назва           — список проектів і перемикання
```

Бот сам вирішує, чи повідомлення — це питання (закінчується на «?» або
починається зі слова на кшталт «яка/скільки/де/знайди») чи новий матеріал
(посилання → парсить сторінку, файл/фото → аналізує, звичайний текст →
зберігає як нотатку менеджера). Питання по одному проекту йде проти
активного проекту (`/project`/`/use`); якщо активного проекту немає, або в
питанні є слова на кшталт «порівняй», «який проект», «найдохідніший» —
бот шукає по ВСІХ збережених проектах одразу (те саме робить `/compare`
напряму). Якщо він щось не так зрозумів — задайте питання явно через
`/ask ...` (по активному проекту) або `/compare ...` (по всій базі).

## Обмеження цієї версії

- Пошук по матеріалах — за ключовими словами, не embeddings: на 5-10
  документів на проект працює добре, на сотні — варто буде підключити
  векторну базу.
- Telegram Bot API дозволяє боту завантажувати файли до ~20 МБ — більші
  фінмоделі/презентації доведеться ділити або надсилати посиланням.
- Розпізнавання зображень (рендери, скани) — через опис Claude vision,
  без OCR координат тексту: для сканованих PDF без текстового шару
  `pypdf` не дістане нічого — у такому разі варто присилати їх як фото.
